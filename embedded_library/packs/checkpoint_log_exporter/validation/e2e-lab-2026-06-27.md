## Observed result

### Initial run before parser fix

The stack started Splunk TEST, but SC4S stayed `health: starting`. SC4S logs showed syslog-ng aborting during config compilation:

```text
Bail out! ERROR:lib/cfg-tree.c:1273:cfg_tree_compile_junction: assertion failed: (node->content != ENC_SOURCE)
ERROR:lib/cfg-tree.c:1273:cfg_tree_compile_junction: assertion failed: (node->content != ENC_SOURCE)
```

This was traced to the Check Point local parser startup path. The parser was changed to keep the timezone-qualified RFC5424 header as primary and avoid overriding it with the structured-data `time` field until live Check Point replay proves timestamp semantics.

### Post-fix stack state

After syncing the parser fix, `PACK_ID=checkpoint_log_exporter scripts/e2e_remote_lab.sh reset-all` reached healthy Splunk TEST and healthy SC4S TEST containers.

SC4S/syslog-ng stats then showed HEC destination activity but no indexed fixture markers in `index=netfw`:

```text
destination;d_hec_fmt;;a;processed;222
dst.http;d_hec_fmt#0;http,https://splunk:8088/services/collector/event;a;written;222
ERROR: expected 5 indexed Check Point Log Exporter fixture events, observed 0
```

A broader Splunk search for the Check Point fixture marker prefix across all indexes also returned no rows.

### Harness failure discovered

The pack send helper masked OpenSSL connection failures with `|| true`, so replay could appear to progress even when no fixture reached the intended listener. During the same lab window, a direct OpenSSL probe later observed refusal on the expected host port:

```text
connect:errno=111
```

A subsequent Docker status sample showed the SC4S container healthy but without the expected host port mapping visible for `20041/tcp`, so the route was not proven end-to-end. The lab then became unreachable over SSH before a clean post-helper-fix rerun could be completed.

## Outcome

Blocked at the replay/listener route. The retained evidence proves:

- the original parser path could crash syslog-ng in the SC4S container;
- after the parser fix, SC4S could start cleanly in the disposable lab;
- Splunk indexed read-back still returned zero Check Point fixture markers;
- the send helper needed fail-closed behavior because it had been hiding OpenSSL send failures.

It does not prove fixture movement through SC4S, HEC delivery for the Check Point events, Splunk indexed read-back, real Check Point source-version behavior, field validation, production readiness, or any trust/quality promotion.
