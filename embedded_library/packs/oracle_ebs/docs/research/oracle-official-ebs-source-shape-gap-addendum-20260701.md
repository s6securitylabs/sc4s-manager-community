## Scope and evidence rule

This addendum tightens the EBS source-shape boundary to **official Oracle public sources only**. Third-party articles, Splunkbase metadata, and non-Oracle eTRM mirrors may be useful triage context, but they are not counted here as official Oracle public evidence for parser-ready native EBS record shapes.

Official docs establish several useful **source families and field concepts**, but they still do not provide enough complete emitted records for universal native EBS parsers. The current `oracle:ebs:security:json` normalized relay remains the only pack-ready mode.

## Timestamp and timezone conclusions

- The normalized relay should continue to require UTC `event_time` because official EBS docs do not establish one shared native timestamp timezone policy across Sign-On Audit, AuditTrail, FND logs, concurrent requests, workflow metrics, OHS, WebLogic, Forms, and DB audit.
- WebLogic explicitly uses the host operating system local timezone/locale for log timestamps.
- OHS access logs use Apache-style request timestamp formatting; OHS rotation options reference UTC offsets, but that is not the same as a universal EBS event timezone.
- AuditTrail documents `AUDIT_TIMESTAMP` as date/time, not an exported timezone-aware string.

## Collection-method conclusions

Supported by official docs as concepts:

- **Table/query/export relay:** Sign-On Audit, AuditTrail shadow tables/views, FND logging records, Workflow Notification Mailer metrics/data sources.
- **File relay:** OHS access/error logs, WebLogic server/domain/security logs, Forms servlet/trace/diagnostic outputs.
- **Normalized JSON relay:** not an Oracle-native format; it is a SecHub/customer-owned safe envelope that can carry approved fields from the above sources.
- **Syslog:** not evidenced as native EBS output for these source families in the retrieved official docs. SC4S is appropriate only after a collector or log forwarder emits the normalized JSON/syslog envelope.

## Dashboard/parser readiness decision

- **Dashboard-ready today:** only the existing `oracle:ebs:security:json` normalized relay dashboard, with explicit curated/unverified status and no exploit/validation claims.
- **Parser-candidate but not EBS-native-ready:** generic OHS default access logs and generic WebLogic server logs have enough official format evidence to justify separate OHS/WebLogic source-family parser work after sample fixtures and read-back. They should not be silently absorbed as validated EBS-native parsers.
- **Normalized-relay-only:** Sign-On Audit, AuditTrail, FND/OAF logging, concurrent request context, Workflow/Notification Mailer metrics, Forms/OAF diagnostics, and APPS activity.
- **Blocked:** universal EBS table/shadow-table parser, exact concurrent manager log parser, Workflow Mailer runtime log parser, EBS-specific OHS/WebLogic/Forms deployment parser, and any dashboard panel requiring exact Payments/File Transmission or ECC event fields beyond advisory tags.

## Evidence still required before promotion

For any selected source mode, collect source-backed evidence with:

1. Oracle EBS version/component and source name (table/view/report/log file/API/metric).
2. One complete sanitized record or row export showing record boundaries, delimiters/escaping, nulls, multiline behavior, and timestamp rendering.
3. Timezone/source clock policy.
4. Collector/export command or forwarder configuration, including whether SC4S sees raw native records, syslog-wrapped records, JSON rows, or a normalized relay.
5. Splunk/SC4S replay and indexed read-back proving event count, source, sourcetype, index, timestamps, required fields, and no unsafe sensitive values.

Until that evidence exists, no `validated`, `s6_verified`, `field_validated`, or native parser-ready claim should be added for `oracle_ebs`.
