# Cisco Duo Audit SC4S TEST → Splunk TEST lab attempt — 2026-06-27

## Scope

Pack: `cisco_duo_audit`

This was a disposable lab retry on `sc4s-validation-lab` to exercise the pack TCP/20088 route through SC4S TEST and Splunk TEST using the synthetic-equivalent fixture file. It does not use a live Duo tenant or Duo API collector.

## Commands run

```bash
PACK_ID=cisco_duo_audit scripts/e2e_remote_lab.sh reset-all
ssh jarvis@10.10.100.180 'cd /opt/sc4s-validation/sechub-resources && packs/cisco_duo_audit/scripts/e2e_docker_compose.sh run'
```

A stale `windows_eventlog` disposable stack first held the shared Splunk TEST ports (`18000`, `18088`, `18089`). It was removed with:

```bash
ssh jarvis@10.10.100.180 'cd /opt/sc4s-validation/sechub-resources && PACK_ID=windows_eventlog scripts/e2e_compose_stack.sh down'
```

## Observed result

The Duo disposable stack reached healthy Splunk TEST and SC4S TEST containers. The send helper transmitted all 12 fixture rows to `127.0.0.1:20088`.

Relevant SC4S/syslog-ng counters from the run showed listener/parser movement:

```text

filter;f_is_source_identified;;a;matched;12
dst.http;d_hec_fmt#0;http,https://splunk:8088/services/collector/event;a;written;68
```

Splunk indexed read-back still returned zero Duo fixture markers:

```text
search index=main "SC4S_CISCO_DUO_AUDIT_TEST_" earliest=-2h | stats count

    0
```

A follow-up all-time marker search also returned no rows:

```bash
docker compose -f .tmp/e2e/cisco_duo_audit/compose.yaml -p sechub-cisco-duo-audit-e2e \
  exec -T --user splunk splunk /opt/splunk/bin/splunk search \
  'search "SC4S_CISCO_DUO_AUDIT_TEST_" earliest=0 | stats count by index sourcetype source host' \
  -auth admin:<redacted>
```

The SC4S container log included an early HEC reachability warning during startup:

```text
SC4S_ENV_CHECK_HEC: Invalid Splunk HEC URL, invalid token, or other HEC connectivity issue index=main. sourcetype=sc4s:fallback
Startup will continue to prevent data loss if this is a transient failure.
```

## Harness correction made from this attempt

The first read-back attempt also exposed noisy Splunk CLI permission warnings because searches were executed as the container default user. The pack harness now runs Splunk CLI searches as `--user splunk` and waits for Splunk HEC health as well as the management endpoint before starting SC4S. This is harness hardening only.

## Evidence boundary

This attempt is **blocked indexed read-back evidence**, not validation. It proves that the fixture reached the pack listener and syslog-ng counters moved, but it does not prove Splunk indexed the fixture events or that Duo API/SIEM connector source behavior is validated. Do not promote `quality_status`, `trust_level`, public Review status, or field-validation posture from this attempt.
